Five projects, built end to end

Schema, server, client, pipelines, deployment and the server they run on — all five are mine from the ground up. Each one below carries the screens it actually ships, and the decisions I would defend in a review.

Deutsches Lernzentrum

A platform language schools run their teaching on.

deutscheslernzentrum.de Source

A school registers a centre, gets a public page and invite codes, and runs its teaching inside the platform: lessons by CEFR level, a quiz builder with auto-grading, vocabulary training, assignments and marking, meeting rooms, chat and a calendar. Students join with a code and track their progress from A1 to C2.

I built it end to end — React 19 front end, Hono and tRPC API, Drizzle and MySQL, JWT auth, S3-compatible uploads, and the Docker production stack it runs on.

Deployment

A push to main is live in three minutes, or it is rolled back

Caddy, the app and MySQL under one docker-compose stack on a single host. Deploys are pull-based: the host notices the commit, builds, health-checks, and reverts to the previous image if the check fails. A deploy that half-succeeds is worse than one that never started, so the failure path is the part that's actually written down.

Migrations

The schema tool that's convenient in development is banned in production

db:push diffs a schema against a live database and applies whatever it infers. Against production it will silently drop a column it believes is redundant. The deployment docs state it must never touch production, and cover how to recover a database that it already has — because writing down the recovery is the only version of that rule that survives somebody being in a hurry.

Documentation

The screenshots regenerate themselves

The in-app guide uses twenty screenshots. Captured by hand, they rot the first time a button moves. A seed script builds one self-contained demo centre, and a Playwright script signs in as four account states and captures all twenty at a fixed size — so “am I about to publish a real student's name?” is never a judgement call. Every image in the carousel above came out of that pipeline.

CareTrack

Care documentation for a ward, offline, on one machine.

caretrack-25m.pages.dev Live demo Tauri v2 desktop application — Windows installer

The paperwork a nurse fills in over a shift — daily care, vital signs, fluid balance, repositioning, wounds, falls, medication, handover — in one application instead of a paper folder. It runs offline against local SQLite, deliberately: care homes have poor coverage in resident rooms, and health data shouldn't leave the building by default.

The handover ties it together, querying every other module for overdue repositioning, out-of-range vitals, missed fluid targets and open post-fall duties, then drafting a note the nurse edits rather than writes from memory.

It is now published: the site carries the Windows installer, and the demo next to it runs the real German interface in a browser against an in-memory stand-in for the Rust backend — so the application can be tried without installing anything.

Audit

The session lives in Rust, so the log is worth reading

Every mutating command writes an audit entry carrying the checksum of the one before it, so a removed or altered row breaks the chain visibly. The acting user comes from process state in Rust — nothing the interface sends can claim an identity. Care documentation is inspected on exactly this basis.

Corrections

Nothing is ever edited; a mistake is superseded in the open

A wrong entry is fixed by appending a replacement that names the row it replaces. The original stays as documented, struck through rather than erased. The chain still verifies because no historical row changed, and a corrected-away value stops counting — a nurse who typed 1500 ml instead of 150 must not still be credited with 1500.

Correction

The tamper check didn't do what I'd written that it did

The test that supposedly proved it deleted a row from the middle of the ledger. Removing rows from the end deletes both sides of every remaining comparison: what's left adds up exactly, and the check reported the ledger intact. The fix records which movement the ledger ended on at each stock count, so a vanished anchor exposes truncation.

Hardening

A second credential path with none of the first one's protections

Confirming a controlled substance takes a witness password — which quietly made that field a place to guess passwords. No lockout check, no failure counting, nothing written to the audit log, and it ran before the ledger was touched, so a run of guesses left no trace. Finding it meant asking which other places accept a password.

Stated limitations

What CareTrack does not do yet

  • No encryption at rest. The hard part is key management, not ciphers: every member of staff signs in to the same database, so a per-user key means re-wrapping the database key on every account change. Until it exists, the app must not hold real resident data.
  • Timestamps are local wall-clock. Duration arithmetic is DST-safe and tested, but during the repeated hour at the autumn change two instants render identically.
  • Not a certified medical device, and not validated against the regulations a real care facility is bound by.

Bike-share Data Platform

Batch, streaming and API data on Citi Bike, end to end on one machine.

Source Docker Compose — one command to provision, one to run

Bike-share operators plan demand, react to weather, and truck bikes from stations that fill up to stations that drain. This platform answers those questions from three kinds of data: millions of historical trips, hourly weather, and the live status of every station.

Spark cleans and aggregates the monthly trip archives into a MinIO data lake and a partitioned Postgres warehouse. A Kafka producer streams station status every minute. dlt loads weather and reference data, dbt and Bruin model and test it, Kestra orchestrates all of it, and Terraform provisions the bucket, schemas and roles.

A Streamlit dashboard reads it as a read-only role: demand, weather impact, rebalancing, a live station map, and the pipeline's own data-quality audit.

Idempotency

Every step can be run twice without doubling anything

Lake months get a _SUCCESS marker, so a re-run skips finished downloads. Spark deletes and reloads one city and month at a time. dlt merges on natural keys with incremental state, and the live upsert refuses an event older than the one it already holds. A backfill that dies halfway is fixed by running it again.

Reconciliation

The warehouse has to agree with Spark, row for row

Spark records raw, clean and rejected counts for every month it loads. A dbt test checks that the fact table's row count matches that audit exactly, so a silently dropped partition fails the build instead of quietly shrinking a chart.

Streaming

At-least-once delivery, with the duplicates handled on purpose

The producer publishes only stations whose report changed, keyed by station so each one's events stay in order. The lake consumer commits offsets only after its Parquet file is written, so a crash re-reads rather than loses messages, and dbt removes the duplicates that choice creates.

Warehouse

Postgres, used the way a cloud warehouse would be

Trips are range-partitioned by month, so a month filter prunes and a reload touches one partition. A BRIN index covers the time column for next to nothing on time-ordered data. The dashboard connects as a read-only role that can see the marts and nothing else.

Solar Call Center Automations

Two n8n workflows for an outbound call center booking solar and roofing appointments.

Source Self-hosted n8n — importable workflow JSON

AI Lead Qualification scores every new lead from 0 to 100 the moment it arrives, logs it to a Google Sheet, returns the score to the dialer, and emails a closer about hot leads with a suggested opening line. Renters and “just curious” leads go to a nurture queue instead of eating a rep's dials.

Missed Call SMS Follow-up waits two minutes after a no-answer, has an LLM draft a short text, forces that text to be compliant in code, logs it, and sends exactly one follow-up an hour later unless the contact replied or opted out.

Both call Claude by default through n8n's core HTTP Request node, with a one-field switch to Gemini. Prompts, thresholds and recipients sit in one config node a sales manager can edit without touching code.

Parsing

The model's answer is read, never trusted

The parser pulls JSON out of code fences and surrounding prose, skips thinking blocks, clamps the score to 0–100 and caps renters in code. The tier comes from the score and the configured thresholds, not from the model, so routing never depends on the model agreeing with itself. Its own tier is kept only for tuning the prompt.

Failures

A lead the AI couldn't score goes to a person

The LLM calls retry three times and then continue on error. A refusal, a timeout or unreadable output becomes scoring_status: failed and emails a closer right away. Parking it in nurture could bury a hot lead, and an outage should turn into manual work, not dropped leads.

Compliance

The prompt asks for a compliant text; the code guarantees it

One curly apostrophe or emoji switches an SMS to UCS-2, where a segment is 70 characters instead of 160 and the message is split and billed several times. The enforcement node converts to plain ASCII, strips whatever opt-out wording the model wrote, appends the exact configured line, and falls back to a fixed template if the draft still doesn't fit.

Ordering

A 200 means the lead is saved

The webhook answers only after the Sheet write. If Sheets is down, the dialer gets an error and retries, so a lead is never acknowledged and then lost. Phone numbers and emails are never sent to the model, because it doesn't need them to score.

Ops Platform

A server I run like production: built from code, watched, backed up, and restored on purpose to prove it works.

Source Live status page Oracle Cloud free tier — Terraform + Ansible

My other projects are applications. This one is the ground they stand on: one ARM server created by Terraform and configured by Ansible, running a reverse proxy, the n8n automations, uptime checks with a public status page, and a metrics stack.

Nothing on it was clicked together by hand. A fresh box reaches the same state from this repository, and a full re-run of the playbook reports changed = 0, which is how I know the code and the machine still agree.

It also backs up a second server: the language-school platform in production. Its nightly database dumps only ever lived on the same disk as the database, so they now go off-site too — without editing a single file that the school's own repository owns.

Infrastructure

The repository is the server

Terraform creates the network, the firewall rules and the instance; Ansible takes it from a fresh Ubuntu image to the running stack — hardening, Docker, the compose file, monitoring and backups. Rebuilding after a total loss is terraform apply, one playbook run and a restore. That claim is only worth something because a re-run reports no changes, so the code hasn't quietly drifted from the machine.

Backups

I deleted the data to find out whether the backups were real

Every night restic sends the volumes to Backblaze, taking consistent SQLite copies while n8n and Uptime Kuma keep serving. A monthly drill restores the newest snapshot, re-verifies a tenth of the stored data and checks the databases. Then I removed n8n's volume outright: the service was back in 31 seconds with every workflow, execution and credential intact — including the encryption key, without which credentials restore as unreadable blobs. The write-up covers what it exposed.

Alerting

Two paths, because a silent monitor looks exactly like a healthy one

Alertmanager reports what is wrong: disk over 80%, a disk that will be full within a day, memory, an out-of-memory kill, a container that vanished. A push monitor reports silence — when a nightly backup doesn't check in within 26 hours, that is its own alert. The drill also measured the blind spot: an outage has to last about three minutes before either path speaks, which is the price of not being trained to ignore Telegram.

Exposure

One way in, and the webhooks cost money

Only the proxy publishes ports; n8n, Grafana and the rest are unreachable except through it, and node_exporter binds to the Docker bridge address instead of the public interface. The n8n webhooks spend LLM quota and send mail, so the proxy rejects anything without a shared-secret header before n8n starts an execution. SSH is key-only, from my address, with repeat offenders banned.
