Deutsches Lernzentrum

A platform language schools run their teaching on.

deutscheslernzentrum.de Source

A school registers a centre, gets a public page and invite codes, and runs its teaching inside the platform: lessons by CEFR level, a quiz builder with auto-grading, vocabulary training, assignments and marking, meeting rooms, chat and a calendar. Students join with a code and track their progress from A1 to C2.

I built it end to end — React 19 front end, Hono and tRPC API, Drizzle and MySQL, JWT auth, S3-compatible uploads, and the Docker production stack it runs on.

Deployment

A push to main is live in three minutes, or it is rolled back

Caddy, the app and MySQL under one docker-compose stack on a single host. Deploys are pull-based: the host notices the commit, builds, health-checks, and reverts to the previous image if the check fails. A deploy that half-succeeds is worse than one that never started, so the failure path is the part that's actually written down.

Migrations

The schema tool that's convenient in development is banned in production

db:push diffs a schema against a live database and applies whatever it infers. Against production it will silently drop a column it believes is redundant. The deployment docs state it must never touch production, and cover how to recover a database that it already has — because writing down the recovery is the only version of that rule that survives somebody being in a hurry.

Documentation

The screenshots regenerate themselves

The in-app guide uses twenty screenshots. Captured by hand, they rot the first time a button moves. A seed script builds one self-contained demo centre, and a Playwright script signs in as four account states and captures all twenty at a fixed size — so “am I about to publish a real student's name?” is never a judgement call. CareTrack

Care documentation for a ward, offline, on one machine.

caretrack-25m.pages.dev Live demo Tauri v2 desktop application — Windows installer

The paperwork a nurse fills in over a shift — daily care, vital signs, fluid balance, repositioning, wounds, falls, medication, handover — in one application instead of a paper folder. It runs offline against local SQLite, deliberately: care homes have poor coverage in resident rooms, and health data shouldn't leave the building by default.

The handover ties it together, querying every other module for overdue repositioning, out-of-range vitals, missed fluid targets and open post-fall duties, then drafting a note the nurse edits rather than writes from memory.

It is now published: the site carries the Windows installer, and the demo next to it runs the real German interface in a browser against an in-memory stand-in for the Rust backend — so the application can be tried without installing anything.

Audit

The session lives in Rust, so the log is worth reading

Every mutating command writes an audit entry carrying the checksum of the one before it, so a removed or altered row breaks the chain visibly. The acting user comes from process state in Rust — nothing the interface sends can claim an identity. Care documentation is inspected on exactly this basis.

Corrections

Nothing is ever edited; a mistake is superseded in the open

A wrong entry is fixed by appending a replacement that names the row it replaces. The original stays as documented, struck through rather than erased. The chain still verifies because no historical row changed, and a corrected-away value stops counting — a nurse who typed 1500 ml instead of 150 must not still be credited with 1500.

Correction

The tamper check didn't do what I'd written that it did

The test that supposedly proved it deleted a row from the middle of the ledger. Removing rows from the end deletes both sides of every remaining comparison: what's left adds up exactly, and the check reported the ledger intact. The fix records which movement the ledger ended on at each stock count, so a vanished anchor exposes truncation.

Hardening

A second credential path with none of the first one's protections

Confirming a controlled substance takes a witness password — which quietly made that field a place to guess passwords. No lockout check, no failure counting, nothing written to the audit log, and it ran before the ledger was touched, so a run of guesses left no trace. Finding it meant asking which other places accept a password.

Stated limitations

What CareTrack does not do yet

  • No encryption at rest. The hard part is key management, not ciphers: every member of staff signs in to the same database, so a per-user key means re-wrapping the database key on every account change. Until it exists, the app must not hold real resident data.
  • Timestamps are local wall-clock. Duration arithmetic is DST-safe and tested, but during the repeated hour at the autumn change two instants render identically.
  • Not a certified medical device, and not validated against the regulations a real care facility is bound by.
